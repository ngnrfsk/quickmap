## Implementation Steps

### Step 1: Create New Directories
```r
dir.create("R")
dir.create("man")
dir.create("inst/examples", recursive = TRUE)
dir.create("tests/testthat", recursive = TRUE)
dir.create("vignettes")
dir.create("dev/archive/tests_legacy", recursive = TRUE)
dir.create("dev/archive/plans", recursive = TRUE)
dir.create("dev/reference", recursive = TRUE)
dir.create("dev/utilities", recursive = TRUE)
dir.create("dev/future_plans", recursive = TRUE)
```

### Step 2: Move Production Files
```bash
# Core code
mv quickmap.R R/quickmap.R

# Examples
mv scripts/create_all_borough_maps.R inst/examples/
mv scripts/prepare_bl_data_with_missing.R inst/examples/
```

### Step 3: Archive Historical Files
```bash
# Tests by version
mkdir -p dev/archive/tests_legacy/{v0.8.7_scaling,v0.8.8_boundaries,v0.8.9_markers,v0.9.0_drafts}
mv tests/test_scaling_*.R dev/archive/tests_legacy/v0.8.7_scaling/
mv tests/test_task_1e_*.R dev/archive/tests_legacy/v0.8.7_scaling/
# ... etc

# Plans
mv plans_reference_documents/2510*.md dev/archive/plans/

# Scripts
mv scripts/do_maps_with_v0.8.3_*.R dev/archive/scripts_legacy/
```

### Step 4: Reorganize Active Files
```bash
# Reference docs
mv plans_reference_documents/OpenAir_*.md dev/reference/
mv plans_reference_documents/PARAMETER_*.md dev/reference/
mv plans_reference_documents/style_guide.md dev/reference/

# Dev utilities
mv scripts/missing_data_stats.R dev/utilities/
mv scripts/refresh_maps_2.R dev/utilities/
mv scripts/test_for_csv_data_path.R dev/utilities/

# Future plans
mv tasks/future_options_*.md dev/future_plans/

# Status
mv tasks/PROJECT_STATUS_SUMMARY.md dev/PROJECT_STATUS.md
```

### Step 5: Create New Test Files
Convert test_step[1-4]_*.R to testthat format in `tests/testthat/`

### Step 6: Create Package Files
- DESCRIPTION
- NAMESPACE (via roxygen2)
- README.md
- NEWS.md
- .Rbuildignore

### Step 7: Clean Up Empty Directories
```bash
rmdir plans_reference_documents
rmdir tasks
rmdir scripts  # if empty
```

## Benefits

### Immediate
1. **Clear separation**: Production vs development vs historical
2. **Standard structure**: Follows R package conventions
3. **Easier navigation**: Logical grouping of related files
4. **Archive transparency**: Historical files clearly marked by version

### Preparation for v0.10.0+
1. **R CMD check compliance**: Ready for package validation
2. **Modular architecture**: R/ directory prepared for file splitting
3. **Testing infrastructure**: testthat framework in place
4. **Documentation system**: roxygen2 + vignettes ready
5. **CRAN readiness**: Follows package submission standards

### Maintenance
1. **Onboarding**: New developers see standard R package structure
2. **CI/CD**: Can add automated R CMD check, test coverage
3. **Installation**: Users can install via devtools::install_github()
4. **Versioning**: NEWS.md + git tags for releases

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Breaking existing workflows | Keep versions/quickmap_0_9_0.R as rollback |
| Users have hardcoded paths | Document migration in README |
| Tests fail after move | Update working directory in tests |
| Git history confusion | Use `git mv` to preserve history |
