## Research Context

The R spatial ecosystem has standardized on **sf** for vector data, with **stars** for regular data cubes and **sftime** for irregular spatiotemporal points ([r-spatial.org](https://r-spatial.org/book/)). Air quality networks (AURN, LAQN) are irregular point data—fixed locations with temporal measurements at varying resolutions (1 second to annual). For sub-annual temporal resolution (monthly, daily, hourly), **sftime** becomes relevant: v0.3.1 (August 2025), CRAN-stable, 125 commits, actively maintained with 1 open issue ([GitHub sftime](https://github.com/r-spatial/sftime)). However, [openairmaps](https://openair-project.github.io/openairmaps/) demonstrates production integration using sf+temporal columns, not sftime. Decision: adopt **sftime optionally in Phase 2** (v0.9.4) for sub-annual features, maintain sf-only pathway for annual aggregations. This dual approach avoids forcing dependency while enabling finer temporal resolution when needed.

Zero user-facing changes—internal refactor only.

Prototype episode animation (48-hour pollution event). **Validates sub-annual feasibility** before committing to hourly features.

**v0.9.5 - Performance + Polish**: Implement progressive disclosure (warn if daily >1000 features, block hourly >500 unless override), marker clustering scaling with temporal resolution, external user testing (local authority + researcher workflows), comprehensive documentation. ## Layer Generalization Strategy (v0.9.2 Implementation Detail)

QuickMap's `get_measurement_layers()` returns list with enabled/data_source/layer_type/temporal fields, processed by `generate_map_layers()` loop filtering years and calling `prepare_generic_layer_data()` → `create_generic_icons()` → `add_layer()` (R/quickmap.R:1561-1634). Adding AURN/LAQN currently requires new list entries, icon types, pollutant column logic—15+ modification points. **v0.9.2 refactor**: Layer configs specify sf data object directly (not environment variable name), icon parameters (shape/color/size), pollutant column name, temporal_resolution field. Factory function `create_layer_config(sf_data, icon_params, pollutant_col, temporal_resolution)` builds configs from loaded data. Universal renderer `add_generic_layer(map, layer_config, temporal_filter, colour_scale)` handles all layer types identically. **Post-refactor extensibility**: Adding network = single config entry in assembly function, zero code changes to rendering pipeline. Validates architecture for future non-AQ applications (ecology, epidemiology).

## Use Case Analysis and Temporal Resolution Extension

**Local authority reporting** (current primary): Annual maps remain sf-only, zero changes. **Animate pollution episodes** (NEW): Officer investigates December 2023 high-pollution event using hourly LAQN data, creates 48-hour animation showing pollution plume movement across borough—requires sftime, autoplay controls, performance optimization for 100 sites × 48 hours = 4,800 features. **Correlate pollution with traffic/activity** (advanced): Researcher overlays hourly NO2 (LAQN sftime layer) with traffic flow data (separate temporal layer), creates side-by-side synchronized animations revealing correlation patterns—requires multi-layer temporal synchronization, common time axis. **Build predictive models** (research): Analyst exports sftime object to statistical model (GAM, random forest) with covariates (traffic, meteorology, hour-of-day), trains pollution predictor, imports predictions back as sftime for validation mapping—quickmap becomes visualization endpoint for modeling workflow. **Data assimilation/fusion** (advanced research): Combine sparse AURN stations, dense LAQN network, diffusion tubes (annual), low-cost sensors (hourly) into single spatiotemporal field via kriging/machine learning—output unified sftime object, map shows model uncertainty alongside predictions. Positions quickmap as research tool beyond reporting.

## Technical Risks and Mitigations

**Coordinate mismatches**: AURN uses WGS84, diffusion tubes use BNG—converter outputs WGS84 universally, add CRS validation. **Memory with sub-annual data**: Daily data = 365 days × 100 sites = 36,500 features; hourly = 8,760 × 100 = 876,000 features (Leaflet performance degrades >10,000 markers)—implement progressive disclosure: default to monthly, warn if daily >1000 features, block hourly maps >500 features unless explicit override, recommend temporal subsetting. **sftime dependency concern**: v0.3.1 is production-ready (CRAN, 125 commits, 1 open issue) but pre-v1.0—make sftime **suggested** not required dependency; sf-only pathway always available; document fallback if sftime unavailable. **Icon overlap**: Marker clustering threshold scales with temporal resolution (annual: 50 sites, monthly: 20 sites, daily: 10 sites). **UI complexity**: Roller menu currently year-only—extend to hierarchical (year → month → day) or date range picker for sub-annual; prototype needed in Phase 1 testing.

## sftime Adoption Decision Summary

**Adopt sftime as *suggested* dependency in v0.9.4**, not required. Rationale: (1) **Maturity adequate**—v0.3.1 (Aug 2025), CRAN-stable, 125 commits, actively maintained (1 open issue), production-ready despite pre-v1.0 status; (2) **Functional necessity**—sub-annual temporal resolution (monthly/daily/hourly) benefits from explicit time column and sftime's spatiotemporal methods; (3) **Risk mitigation**—suggested dependency means users without sftime default to sf-only pathway (annual aggregations work unchanged); (4) **Ecosystem alignment**—sftime is r-spatial project (same maintainers as sf/stars), integration well-supported. **Fallback strategy**: Converter returns sf for annual, sftime for sub-annual; if sftime unavailable, degrade gracefully (warning + convert sftime → sf with temporal info in regular column). This positions quickmap for advanced temporal features while maintaining simple annual workflow compatibility.
