## Option 1: leaflet.extras2 (R Package) - addTimeslider

### Description
R package providing `addTimeslider()` function - wrapper for LeafletSlider.js jQuery plugin.

### CRITICAL LIMITATIONS (Research Verified)

**1. No Group Support**
`addTimeslider()` does NOT include a `group` parameter (verified from source code):
- ❌ Cannot assign timeslider markers to named groups
- ❌ Cannot control visibility with `addLayersControl`
- ❌ Cannot use `hideGroup()`/`showGroup()`
- ❌ Cannot integrate with existing group-based architecture
- ✅ Can only use `removeTimeslider()` to remove ALL markers

**Function signature** (no group parameter):
```r
addTimeslider(map, data, radius, stroke, color, weight, opacity,
              fill, fillColor, fillOpacity, dashArray, popup,
              popupOptions, label, labelOptions, ordertime, options)
```

**Compare**: Other functions like `addVelocity()` include `group` parameter for integration with layer control.

**2. Single Layer Only**
LeafletSlider.js (underlying plugin) **cannot handle multiple layers**:
- Quote from plugin author (GitHub Issue #43): "You would have to somehow bring the features from the different layers into one array"
- ❌ Cannot have separate DT, BL, and Schools layers
- ❌ Must combine ALL features into single sf object
- ❌ No way to differentiate marker types within timeslider

**3. Different Data Types Problem**
Current architecture uses different marker types:
- Circles (DT sites) - `create_generic_icons()` with circle shape
- Diamonds (BL nodes) - custom SVG icon
- Crosses (Schools) - different icon

**Timeslider limitation**: All markers rendered identically (circles with radius parameter). Cannot mix icon types.

### Implementation (IF Attempted)

```r
library(leaflet.extras2)

# PROBLEM 1: Must merge ALL data sources into single sf object

# Required: One combined dataset with time column

# PROBLEM 3: All rendered as circles (lose diamond/cross icons)

  addTimeslider(
    data = all_data,  # Single layer, all features

      position = "bottomleft",

  # No addLayersControl() - timeslider handles visibility
  # Cannot use groups - not supported
```

### Complexity: **VERY HIGH (BREAKING)**

**Major Refactoring Required**:
1. Restructure entire data loading system
2. Merge DT + BL + Schools into single sf object
3. Abandon group-based architecture entirely
4. Lose marker type differentiation (circles, diamonds, crosses)
5. Rebuild layer generation (~500 lines)
6. Handle static layers (schools) with fake timestamps?
7. Remove all `addLayersControl()` logic

**Code Changes**:
- `generate_map_layers()` - **complete rewrite** (currently ~200 lines)
- `add_layer()` - **cannot use** (incompatible with timeslider)
- `create_generic_icons()` - **unused** (timeslider only supports circles)
- Data preparation - merge all sources before mapping
- Remove `addLayersControl()`, `hideGroup()`, `showGroup()` calls

### Advantages
✅ R-native solution (no custom JavaScript)
✅ Maintained R package (CRAN)
✅ Integration with existing leaflet pipe
✅ Built-in slider styling

### Disadvantages
❌ **INCOMPATIBLE with group-based architecture** (no group parameter)
❌ **INCOMPATIBLE with multiple data sources** (single layer only)
❌ **LOSE marker differentiation** (circles, diamonds, crosses → all circles)
❌ **Cannot mix with other controls** (no group support)
❌ Requires sf objects (not current marker approach)
❌ All years must be loaded upfront (memory impact)
❌ Static layers (schools) problematic - what timestamp?
❌ Breaking change to entire map generation system
❌ **Future OpenAir compatibility uncertain** - still requires single sf object

### OpenAir Format Compatibility

**OpenAir data format requirements** (verified):
- Column named `date` (POSIXct or Date class)
- Standard names: `ws`, `wd`, `site` (if present)
- Timezone: UTC/GMT (not local with DST)

**Problem**: OpenAir format solves the time column requirement, but:
- ❌ Still doesn't add `group` parameter support to `addTimeslider()`
- ❌ Still limited to single layer (can't separate DT/BL/Schools)
- ❌ Still lose marker type differentiation

**Future OpenAir migration would require**:
1. Data format change (✅ compatible with timeslider)
2. **Architecture change** (still needs single-layer approach)
3. **Loss of features** (marker types, separate layers)

### Recommendation
**STRONGLY NOT RECOMMENDED**

**Reasons**:
1. **Verified incompatibility** with current group-based architecture
2. **Cannot support multiple data sources** (DT + BL + Schools)
3. **Loses visual differentiation** of marker types
4. **Breaking change** with no clear benefit
5. **Future OpenAir format doesn't solve core limitations**

Even with OpenAir format data, `addTimeslider()` remains incompatible with:
- Multi-layer architecture
- Group-based controls
- Different marker types
- Integration with `addLayersControl()`

**Better path**: Use simpler HTML slider (Option 2) that works with existing groups, preserve marker differentiation, maintain architecture flexibility for future OpenAir migration.

## Option 2: HTML5 Range Slider + CSS (Pure Front-End)

### Description
Add HTML range slider via post-processing in `apply_custom_layout_in_html()`. Use CSS for styling, JavaScript for year switching logic.

### VIABILITY VERIFIED (See: v0.9.1_option2_viability_test.md)

**Previous concern**: "HTML/CSS controls cannot communicate with JavaScript-based Leaflet controls"

**Research findings**:
✅ **SOLVED**: `HTMLWidgets.find(selector)` provides direct access to map instance
✅ **VERIFIED**: Standard Leaflet API (`eachLayer`, `addLayer`, `removeLayer`) works with groups
✅ **CONFIRMED**: Event listeners can trigger Leaflet methods
✅ **TESTED**: Multiple Stack Overflow examples show this pattern working

**Access method**:
```javascript

// Now can use full Leaflet API

  if (layer.options.group === year) {
    map.addLayer(layer);  // or removeLayer(layer)
  }
});
```

## Option 3: Leaflet Custom Control (JavaScript Plugin)

### Description
Create custom Leaflet control extending `L.Control` class. Integrates directly with Leaflet API.

### Implementation
```javascript
L.Control.YearSlider = L.Control.extend({
  options: {
    position: 'bottomleft',
    years: [],
    initialYear: null,
    autoPlay: false,
    speed: 1000
  },

  onAdd: function(map) {
    const container = L.DomUtil.create('div', 'leaflet-year-slider');

    // Create slider element
    this._slider = L.DomUtil.create('input', 'year-slider-input', container);
    this._slider.type = 'range';
    this._slider.min = 0;
    this._slider.max = this.options.years.length - 1;
    this._slider.value = this._getInitialIndex();

    // Add labels
    this._yearDisplay = L.DomUtil.create('div', 'year-display', container);
    this._updateDisplay(this.options.years[this._slider.value]);

    // Add play/pause button
    this._playButton = L.DomUtil.create('button', 'play-button', container);
    this._playButton.textContent = '▶';

    // Event handlers
    L.DomEvent.disableClickPropagation(container);
    L.DomEvent.on(this._slider, 'input', this._onSliderChange, this);
    L.DomEvent.on(this._playButton, 'click', this._togglePlay, this);

    this._map = map;
    return container;
  },

  _onSliderChange: function(e) {
    const index = parseInt(e.target.value);
    const year = this.options.years[index];
    this._showYear(year);
    this._updateDisplay(year);
  },

  _showYear: function(year) {
    // Hide all years
    this.options.years.forEach(yr => {
      this._map.eachLayer(layer => {
        if (layer.options && layer.options.group === yr) {
          this._map.removeLayer(layer);
        }
      });
    });

    // Show selected year
    this._map.eachLayer(layer => {
      if (layer.options && layer.options.group === year) {
        this._map.addLayer(layer);
      }
    });
  },

  _togglePlay: function() {
    // Animation logic here
  },

  onRemove: function(map) {
    // Cleanup
  }
});

// Usage in R
map %>% htmlwidgets::onRender("
  function(el, x) {
    const map = this;
    new L.Control.YearSlider({
      years: ['2017', '2018', '2019', '2020', '2021', '2022', '2023', '2024'],
      initialYear: '2024',
      position: 'bottomleft'
    }).addTo(map);
  }
")
```

### Complexity: **MEDIUM-HIGH**

**Changes Required**:
1. Create JavaScript plugin file (~200 lines)
2. Include plugin in HTML via `apply_custom_layout_in_html()`
3. Inject initialization script with `htmlwidgets::onRender()`
4. Add CSS for custom control styling
5. Remove `addLayersControl()`
6. Test integration with map lifecycle

**R Code Changes**:
- Minimal R changes (just injection of JS/CSS)
- Most logic in external JavaScript file

### Advantages
✅ **Proper Leaflet integration** - follows Leaflet patterns
✅ Works with current group structure
✅ Can be packaged as reusable plugin
✅ Full control over behavior and styling
✅ Handles map events properly (zoom, pan, etc.)
✅ Professional code organization
✅ Easier to debug than inline scripts

### Disadvantages
❌ More complex than simple HTML slider
❌ Need to manage external JavaScript file
❌ Requires understanding of Leaflet API
❌ Still requires custom JavaScript maintenance
❌ More boilerplate code

### Recommendation
**Alternative to Option 2** - Better if you plan to reuse control across multiple projects or want cleaner code organization. Otherwise Option 2 is simpler.

### Phase 2 Results - Layer Control ❌

**Critical Issue Discovered**: Layer cache initialization timing problem

#### Problem: Hidden Layers Not Cached

**Root cause**: Fix #2 (v0.9.0.1) hides non-latest year groups on map load via `hideGroup()`. When caching layers from HTML using `map.eachLayer()`, only **visible** layers are iterated, not hidden ones.

**Observed behavior**:

2. Cache contains: `{2022: 0, 2023: 0, 2024: 54}`
3. Slider moves from 2024→2023: Removes 54, adds 0 → map empty
4. Moving back 2023→2024: Adds 54, removes 0 → map reappears

**Console output**:
```

Year switched to "2023" - Added: 0 Removed: 54
```
