## Fix #3: Zoom Level on Map Open (Priority: HIGH)

### Issue
Maps may open with excessive empty borders, not utilizing screen space efficiently. Markers should fill the viewport with minimal padding.

**Challenge**: Maps could be opened on:
- Tall and narrow screens (mobile portrait)
- Wide screens (landscape mobile/tablet/laptop/desktop)

**Strategy required**: Zoom to reasonable level in either case.

### Current Behavior
```r
# In create_pollution_map(), likely using default zoom
map <- leaflet() %>% addTiles()
# May not be calculating optimal bounds from data
```

### Initial Proposed Solution (NEEDS REVISION WITH USER)
Calculate bounds from actual marker locations and use `fitBounds()`:

```r
# After loading all data, before creating map
calculate_optimal_bounds <- function(data_layers) {
  # Collect all lat/lon from all active layers
  all_coords <- bind_rows(
    dt_coords,
    sensor_coords,
    school_coords
  )

  # Calculate bounding box with small padding
  list(
    lng_min = min(all_coords$lon) - 0.01,
    lng_max = max(all_coords$lon) + 0.01,
    lat_min = min(all_coords$lat) - 0.01,
    lat_max = max(all_coords$lat) + 0.01
  )
}

# Apply to map
map <- map %>% fitBounds(
  bounds$lng_min, bounds$lat_min,
  bounds$lng_max, bounds$lat_max
)
```

### Strategy Questions for User

1. **Padding Approach**:
   - Fixed padding (e.g., 0.01 degrees ~1km)?
   - Percentage-based padding (e.g., 5% of data extent)?
   - Different padding for narrow vs wide viewports?

2. **Aspect Ratio Handling**:
   - Should zoom be constrained differently for portrait vs landscape?
   - Should there be a maximum zoom level (avoid zooming too far in)?
   - Should there be a minimum zoom level (avoid zooming too far out)?

3. **Edge Cases**:
   - Single marker: What default zoom level?
   - Very dispersed markers: Accept large empty areas or cap zoom-out?
   - Multiple boroughs: Fit all or focus on primary borough?

4. **Viewport Detection**:
   - Should the code detect viewport size and adjust zoom accordingly?
   - Or rely on leaflet's fitBounds() to handle automatically?

### Recommended Strategy (Pending User Approval)

**Option A: Simple Fixed Padding**
- Calculate bounding box from all markers
- Add 5% padding to lat/lon extents
- Use `fitBounds()` without constraints
- Pros: Simple, predictable
- Cons: May not be optimal for extreme aspect ratios

**Option B: Percentage-Based Adaptive Padding**
- Calculate bounding box from all markers
- Add 2-10% padding based on data spread
- More padding for tight clusters, less for dispersed data
- Pros: Adapts to data characteristics
- Cons: More complex logic

**Option C: Zoom Level Constraints**
- Calculate bounding box as in Option A/B
- Set `maxZoom` and `minZoom` constraints in fitBounds()
- Prevent extreme zoom levels
- Pros: Prevents edge case issues
- Cons: May still show empty space in some cases

**User Decision Required**: Which strategy should be implemented?
