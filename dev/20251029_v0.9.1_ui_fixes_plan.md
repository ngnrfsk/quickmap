## Fix #1: Zoom Level on Map Open (Priority: HIGH)

### Issue
Maps may open with excessive empty borders, not utilizing screen space efficiently. Markers should fill the viewport with minimal padding.

### Current Behavior
```r
# In create_pollution_map(), likely using default zoom
map <- leaflet() %>% addTiles()
# May not be calculating optimal bounds from data
```

### Proposed Solution
Calculate bounds from actual marker locations and use `fitBounds()`:

```r
# After loading all data, before creating map
calculate_optimal_bounds <- function(data_layers) {
  # Collect all lat/lon from all active layers
  all_coords <- bind_rows(
    dt_coords,
    sensor_coords,
    school_coords
  )

  # Calculate bounding box with small padding
  list(
    lng_min = min(all_coords$lon) - 0.01,
    lng_max = max(all_coords$lon) + 0.01,
    lat_min = min(all_coords$lat) - 0.01,
    lat_max = max(all_coords$lat) + 0.01
  )
}

# Apply to map
map <- map %>% fitBounds(
  bounds$lng_min, bounds$lat_min,
  bounds$lng_max, bounds$lat_max
)
```

### Implementation Steps
1. **Locate** map initialization in `create_pollution_map()` (~line 2300)
2. **Add** `calculate_optimal_bounds()` helper function
3. **Collect** coordinates from all enabled layers
4. **Apply** `fitBounds()` before rendering
5. **Test** with different data combinations (DT only, BL only, both)

### Files to Modify
- `R/quickmap.R` - Add helper function (~20 lines)
- `R/quickmap.R` - Modify map creation section (~5 lines)

### Test Cases
- ✓ Single borough (Merton) - fills screen appropriately
- ✓ Multiple boroughs - encompasses all
- ✓ DT data only - bounds correct
- ✓ BL data only - bounds correct
- ✓ Schools only - bounds correct
- ✓ No data - falls back to default borough bounds

### Success Criteria
- No visible empty borders exceeding 5% of viewport
- All markers visible on initial load
- Padding proportional (small but visible margin)

## Fix #2: Select Start Layer (Priority: HIGH)

### Issue
Users cannot specify which year/layer is visible when map first loads. Currently defaults to first year or all years visible.

### Current Behavior
```r
# All years may be visible initially, or first year
# No user control over initial state
```

### Proposed Solution
Add `initial_year` parameter to control which layer shows first:

```r
create_pollution_map <- function(
  ...,
  years = NULL,
  initial_year = NULL,  # NEW: which year visible on load
  ...
) {
  # If initial_year not specified, use first year or "latest"
  if (is.null(initial_year)) {
    initial_year <- if (is.null(years)) "latest" else years[1]
  }

  # When adding layers, set group visibility
  for (yr in all_years) {
    group_name <- paste0("Year ", yr)
    visible <- (yr == initial_year)

    map <- addLayersControl(
      ...,
      options = layersControlOptions(
        collapsed = FALSE
      )
    )

    # Hide non-initial layers
    if (!visible) {
      map <- hideGroup(map, group_name)
    }
  }
}
```

### Implementation Steps
1. **Add** `initial_year` parameter to function signature (~line 2144)
2. **Add** logic to determine default initial year
3. **Modify** layer addition loop to track visibility
4. **Use** `hideGroup()` for non-initial layers
5. **Update** roxygen documentation

### Files to Modify
- `R/quickmap.R` - Function signature (~line 2144)
- `R/quickmap.R` - Layer generation logic (~line 2315-2350)
- `R/quickmap.R` - Documentation header (~line 2050-2100)

### Parameter Options
```r
initial_year = NULL        # Default: first year or latest
initial_year = 2024        # Specific year
initial_year = "latest"    # Most recent year in data
initial_year = "earliest"  # Oldest year in data
```

### Test Cases

- ✓ `initial_year = NULL` - First year visible (default)
- ✓ `initial_year = "latest"` - Most recent year visible
- ✓ `initial_year = 2020` when 2020 not in data - warning + fallback
- ✓ Static layers (schools) always visible regardless

### Success Criteria

- Radio buttons allow switching between years
- No JavaScript errors in console

## Fix #3: Collapsible Radio Buttons (Priority: MEDIUM)

### Issue
Year selection radio buttons take up screen space and should:
1. Be collapsible to save space
2. Be positioned in bottom-left corner (standard UI pattern)

### Current Behavior
```r
# Leaflet layersControl likely in default position (top-right)
addLayersControl(
  baseGroups = c("Year 2021", "Year 2022", ...),
  position = "topright",  # Default
  options = layersControlOptions(collapsed = FALSE)
)
```

### Proposed Solution
Move control to bottom-left and make collapsible:

```r
addLayersControl(
  baseGroups = year_groups,
  position = "bottomleft",  # NEW position
  options = layersControlOptions(
    collapsed = TRUE,  # Start collapsed
    autoZIndex = TRUE
  )
)
```

**CSS Enhancement** (via `apply_custom_layout_in_html()`):
```css
/* Position and style year control */
.leaflet-control-layers.leaflet-control {
  bottom: 20px !important;
  left: 20px !important;
  top: auto !important;
  right: auto !important;
}

/* Collapsed state styling */
.leaflet-control-layers-toggle {
  background-image: url(calendar-icon.svg);
  width: 36px;
  height: 36px;
}

/* Expanded state */
.leaflet-control-layers-expanded {
  padding: 8px 12px;
  background: rgba(255, 255, 255, 0.95);
  border-radius: 4px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.2);
}

/* Mobile responsive */
@media (max-width: 768px) {
  .leaflet-control-layers {
    bottom: 10px !important;
    left: 10px !important;
  }
}
```

### Implementation Steps
